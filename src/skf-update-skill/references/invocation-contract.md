# Invocation Contract: skf-update-skill

The argument set, gate map, outputs and headless result line of `skf-update-skill`. Headless callers and pipeline integrators read it; an interactive run needs it only to look up a flag.

| Aspect | Detail |
|--------|--------|
| **Inputs** | skill_name [required]: the skill's name or folder path, as the argument. With none, an interactive run offers the skills SKF generated, and a headless run halts `blocked` (`error.phase` `init:skill-name`, `error.reason` starting `input-missing`) |
| **Flags** | `--headless` / `-H`; `--from-test-report` (gap-driven mode; with no finished test report a headless run halts `blocked` at `init:test-report` and an interactive one warns `test-report-missing` and runs a normal update); `--target-ref <ref>` (normal mode, a skill forged from a remote repository: read a tag, a branch, `HEAD` (the default branch) or a full 40-character commit instead of the recorded `source_ref`, and record it as the new `source_ref` when the update writes); `--source-root <path>` (a skill read from a local folder: read the source there, warn `source-root-overridden`, and record it as `source_root` when the update writes; any other skill halts `blocked`); `--allow-workspace-drift` (gap-driven only: each gap that needs the pinned tree halts `halted-for-workspace-drift` before merge, gap-spot-check.md §3b); `--allow-degraded` (headless only: take load-baseline.md §4's degraded rebuild when no provenance map is found, instead of halting `blocked`); `--detect-only` (status `detect-only`); `--dry-run` (status `dry-run`, writes nothing in any mode; a gap-driven.md or gap-spot-check.md halt such as `halted-for-remediation-path` or `halted-for-workspace-drift` still stops it). init.md §1 describes each; `--detect-only` wins over `--dry-run`. |
| **Gates** | step 1b: load-baseline.md §4's degraded-rebuild gate [D]/[X] when no provenance map is found (headless: halts, or takes [D] under `--allow-degraded`; a gap-driven run halts `blocked` there instead); load-baseline.md §4b's [G]/[S] test-report offer, interactive only (headless warns `unconsumed-test-report`); Confirm Gate [C] (load-baseline.md §8) | step 2a, each only when triggered: reconcile-scope.md §1b's promote prompt and §1c's scope-expansion prompt [P]/[S]/[U] (headless: defers each candidate to a person) | step 2, only when triggered: detect-changes.md §2.2's deletion-ratio gate [C]/[B]/[A] (headless: [C]) | step 2g (gap-driven): gap-driven.md §1 rule R1's [D]/[R] for each gap whose remediation names removal (headless: [D], or [R] only when the export is internal or `#[doc(hidden)]`) | step 4: merge.md §4's [K]/[R]/[E] for each [MANUAL] conflict (headless: [K] for a POSITION conflict, recorded as `merge.manual-conflict`; an ORPHAN or STALE_REFERENCE conflict halts `halted-for-manual-mismatch` before anything is written); a clean or resolved merge goes straight to write |
| **Outputs** | A new version folder `{skill_group}/{new_version}/` and its forge folder, beside the unchanged previous version (a gap-driven repair writes the current version in place), and a finished run's `update-skill-result-{YYYYMMDD-HHmmss}.json` and `update-skill-result-latest.json` in that version's forge folder (a run that found no change: the current one's). `--detect-only` and `--dry-run` write none of these, nor the skill brief. Run state goes to a run folder under `{project-root}/_bmad-output/.skf-run/` that step 7 removes; a halt keeps it |
| **Concurrency** | A second real update of the same skill halts `halted-for-concurrent-run` while the first holds its run lock (init.md §1b); `--detect-only` and `--dry-run` take no lock. verify-publish.md §8 halts with the same status when another flip of the `active` link holds its lock for 5 seconds. A remote skill is read from a private tree, and no mode writes to the shared workspace clone before verify-publish.md §9. |
| **Headless** | No gate prompts: each resolves as the Gates row says, and the run records the decision. One `SKF_UPDATE_RESULT_JSON` line (report.md §5b), at step 6 or at a HALT, printed by the shared emitter and checked against `shared/scripts/schemas/skf-update-result-envelope.v1.json`. It is the run's last line: the shared health check displays it after everything else; a HALT displays its line and stops. Pipelines branch on `skf_update.status`: `success`, `no-changes`, `detect-only` and `dry-run` are successful exits. A headless run whose emitter refused its result line for good ends on a `halted-for-write-failure` line instead, with `error.phase` `report:result-contract` and an `error.reason` that starts `result-contract-not-written`, and nothing it wrote is undone. A caller reads the run's own `SKF_UPDATE_RESULT_JSON` line. A run that printed no envelope line has no result to read, whatever the process exit code: it was cut off, or could not write its result, and `update-skill-result-latest.json` may then describe an earlier run, so it is never read in its place. |
