# Source Access Protocol

## Source API Surface Definition

**Source API surface** = the package's top-level public exports. These are the symbols reachable from the primary entry point without importing internal modules:

- **Python:** symbols exported in the package root's `__init__.py` (including re-exports), excluding private (`_prefixed`) names. A sub-package behind a folder with no `__init__.py` (a FastAPI `routers/__init__.py`, say) is not a second package root when the folder of another package root that exports a name holds it, unless `scope.include` or `scope.tier_a_include` lists that `__init__.py`: its names stay out of the `all` and `root` sets (`excluded.nestedEntries`), while the `scope.include` and `tier_a_include` sets still count them and their signatures are still compared
- **TypeScript/JavaScript:** named exports from `index.ts` / `index.js` — exclude unexported locals
- **Go:** exported identifiers (capitalized) from the package's public-facing files
- **Rust:** items in `pub use` from `lib.rs` or `mod.rs`

The clauses below decide which part of that surface is the coverage denominator. `load-coverage-inputs.py surface` picks the clause from the brief (`{forge_data_folder}/{skill_name}/skill-brief.yaml`), `{source_is_monorepo}` (coverage-check.md §0b, passed as `--monorepo`), the extraction and `metadata.json`, and writes it to `surface.json` `denominator` with the branch, the name set, the rung it takes (coverage-check.md §2b) and the entry points' state it read (`barrel`), beside the counts each clause names (`sets`, `candidates` and `guards`). A workspace member counts toward `{source_is_monorepo}` only through the files the brief keeps: excluding its source files drops it, excluding only its manifest does not, and a workspace with no member left is no workspace. Three of its inputs are yours to pass as flags, the last two only where no file gives them:

- **Pattern-reference intent** (`--pattern-reference-intent`): `scope.notes` says the skill demonstrates an integration pattern rather than a library API ("Reference app, not a library", "pattern-reference", "embedded-pattern skill", "skill value is the … pattern"; the author's words are authoritative).
- **A curated monorepo subset** (`--curated-subset`), where the extraction has no `counts.curated_subset` (Quick tier, the fallback per-file scan, States 2 to 4): `{source_is_monorepo}` is true and the brief's `scope.include` lists a curated subset rather than the full workspace.
- **The entry points' state** (`--barrel`), where no complete extraction or quick output gives it (the fallback per-file scan when the runner listed entry points, Quick tier read by eye, State 4): `none` when no barrel file is at any recognized entry-point path (`__init__.py`, `index.ts`/`index.js`, `lib.rs`, `mod.rs`), `empty` when the primary entry point exports nothing (`export {};`, an empty `__init__.py`, a `lib.rs` with no `pub use`), else `barrel`.

Never re-count a barrel by hand. A `scope.tier_a_include` glob counts a name only in a file a `scope.include` glob also matches, and one that matches no file (`guards.staleScope.unmatchedTierAInclude`, a brief older than the source) counts none: when the tier A globs count no name, `surface.json` has no `tier_a_include` set. coverage-check.md §5's render writes each clause's `Denominator:` line from these counts (`surface.json` `candidates`). Each clause, by its `denominator.clause`, with what stays yours:

- **Empty-barrel packages (`empty-barrel`; copy-paste or subpath-only distribution):** the primary entry point is empty, so the denominator is the `scope.include` set. The brief's `scope.notes` should say the distribution model is by design; when it does, treat the empty barrel as intended rather than a bug. With no brief and an empty barrel, set `analysis_confidence: docs-only` and report that the source API surface could not be determined.

- **Stratified-scope monorepo packages (`stratified-scope`; curated subsets of multi-package repos):** the denominator reflects only the authored surface, not the monorepo's global export count: the `stats.effective_denominator` Create Skill stored, unless `guards.deflation.fires` (a Medium `metadata-drift` gap, coverage-check.md §4: a legitimate scope reduction goes in the brief, through `scope.tier_a_include` or `scope.exclude`, never into `metadata.stats`), then the `tier_a_include` set when the guard measured the stored count against it (`guards.deflation.basis` `tier_a_include`, in either direction: a stale count, which re-running Create Skill recounts, storing the runner's tier A count when `effective_denominator_decision.store` holds and `scope.notes` documents the stratification and otherwise dropping the stored count; on an incomplete extraction a set below the stored count leaves the stored count), else the `scope.include` set; with no stored count, the `tier_a_include` and `scope.include` sets. Never set `stats.effective_denominator` by hand: Update Skill's recount drops it. When `guards.inflation.fires` (the coarse globs sweep in internal infrastructure, a Medium `denominator-inflation` gap), the `scope.include` union is itself inflated: when the deflation guard fires too, that union stays the denominator and both gaps ask for a `scope.tier_a_include` list of the files that define the authored names (when `guards.umbrella.umbrella` is true, those files rather than the barrel). When the barrel branch counts that union, here or on the multi-entry ladder, the names it counts and the skill does not document are one more `denominator-inflation` gap beside the guard's at the brief, which defers to the guard's fix, not a `missing-export` gap each. Leave `analysis_confidence` unchanged. `scope.notes` should document the stratification (for example "Tier A: fully documented; Tier B: deferred to references; Tier C: excluded"); when it does, treat the curated subset as intended, not a scope gap.

- **Standard barrel (`standard-barrel`, the `all` set):** `full-library` skills, single-package repositories and briefs where the full monorepo is intentionally in scope. A `scope.include` glob that matches no file (a brief written for an older layout of the source) does not shrink that barrel: `guards.staleScope` restores the root exports defined in a file no glob covers, unless `scope.exclude` or a `scope-expansion` amendment whose latest action is `skipped` or `demoted-include` matches the file. The stale glob is a Medium `brief-scope-stale` gap (coverage-check.md §4), which also names each `scope.tier_a_include` glob that matches no file.

- **Pattern-reference apps (`pattern-reference`; non-library source):** a single-package repo that demonstrates an integration pattern rather than distributing a library API. The denominator is the `tier_a_include` set when `surface.json` has it, else the canonicalized provenance map, since `skf-create-skill`'s extraction already curated the map to the authored pattern surface. Leave `analysis_confidence` unchanged.

- **Single-crate curated subset (`specific-modules`):** a single-package repo whose brief carves a subset of the crate's public surface with `scope.include` and `scope.exclude`: the in-scope reachable barrel, or the `stats.effective_denominator` Create Skill stored for it, under the same deflation guard.

- **Multi-entry (exports-map) packages (`multi-entry`):** an in-scope `package.json` declares an `exports` map with more than one non-root subpath (`extraction.arms.multi_subpath_exports`). Installers reach every published subpath, so the denominator is the `subpaths` set (wildcard subpaths are left out: their surface is unbounded), or a stored count or `tier_a_include` set ahead of it, the stored count under the same deflation guard, whose fire counts the `tier_a_include` set when the surface has it, else the `scope.include` set. The root-barrel count (`candidates.rootBarrel`) is the secondary candidate in the Denominator Candidates block coverage-check.md §5's render writes.

Internal module symbols are **excluded** from the coverage denominator unless they are explicitly documented in SKILL.md (in which case they count as documented extras, not missing coverage): the surface's names are only those the entry points export, and the extraction's `internal` names reach it only as `internalDeclarations` (What the Surface Holds, below), which add no name to its sets or to the coverage denominator. A documented extra reaches coverage-check.md §2c as a stale name.

### Provenance-map canonicalization

A provenance map may hold **bookkeeping variants** of one export, artifacts of how the library structures its registry (Storybook's component-plus-story decomposition, accessibility renderer shadowing, exact-match renderer disambiguation). Counting them as separate exports inflates the denominator with names that are structural duplicates of a documented base export. When a clause takes its denominator from the provenance map, pass `--fold` to `surface`: it folds `X_def`, `X_exact` and `a11y_X` back to `X`, and `<prefix>X` back to `X` for each renderer prefix you pass as `--fold-prefix` (`mobile_`, `web_`, `ssr_`, only folded when `X` is an entry too), and reports the fold summary in `canonical.summary` for the report. Test-skill defines this fold convention: the base form is authoritative, and the variant is a sibling record. The provenance line check (coverage-check §4c) applies the same three rules, without `--fold-prefix` or `--keep`, when the cited file never names the variant: it checks the line against `X`.

A map whose raw count equals `stats.effective_denominator` is already canonical: `surface` folds nothing (`canonical.skipped`). A non-zero `canonical.residual` after folding (raw 222, canonical 215, `effective_denominator` 216) is an unexplained-reconciliation note; do not invent fold rules to close it. One judgment stays here: a variant the library's public surface genuinely distinguishes (an `a11y_Checkbox` documented and installed on its own) is a real export: pass it as `--keep`. Check SKILL.md for explicit documentation of the variant first; when in doubt, keep it and report both forms.

### What the Surface Holds

`surface.json` holds the names the entry points export, less those defined in a file the brief scopes out (`excluded.outsideScope`); the recipes' internal matches are never part of it. Beside them it lists the nested entries the `all` and `root` sets leave out (`excluded.nestedEntries`), the root exports a stale `scope.include` glob restores to it (`guards.staleScope.restored`), and `otherDeclarations` and `internalDeclarations` (the declarations no entry point exports, of a name the surface holds and of one it does not), which add no name to a set or a count and are `null` when no runner extraction looked for them. §5's render lists the excluded and restored names, and `plan`, `score` and coverage-check-branches.md's Split-Body Sources read the two declaration lists as a name's declarations.

## Source Access Resolution

Before analysis, determine source access level. Walk through these states in order — use the first that succeeds:

**State 1 — Local source available:**
`{run_dir}/access.json` (coverage-check.md §0b) gives `state` 1: `{source_path}` (from metadata.json `source_root`) is a folder on disk. Full analysis at detected tier (AST + signatures). Set `analysis_confidence: full`.

**State 2 — Local absent, provenance-map exists:**
`access.json` gives `state` 2: `{forge_provenance_map}`, the provenance map init.md §2 bound (the skill version folder's, or the flat copy an older skill may still keep), holds `provenanceEntryCount` entries, at least 1. Use it as the baseline export inventory. Each entry contains the structured fields `export_name`, `export_type`, `params[]`, `return_type`, `source_file`, `source_line`, `confidence`, and `ast_node_type`. Set `analysis_confidence: provenance-map`.

**Cross-reference with metadata.json:** the coverage denominator is the **union** of the provenance-map named exports and the `metadata.json` `exports[]` names, which `surface --provenance --metadata` (coverage-check.md §2) builds: an export in metadata but absent from the map counts as missing documentation, and the `state2` counts (`provenanceCount`, `metadataCount`, `unionCount`) go to step 5, whose scoring script decides whether the two disagree enough for the State 2 undercount deduction. When the union exceeds the map, report: "Provenance-map contains {provenanceCount} named exports but metadata.json lists {metadataCount} exports. Coverage denominator uses the union ({unionCount})." With no `metadata.json` `exports[]`, the map alone is the surface, with the note "Coverage denominator is provenance-map only: it may undercount if extraction was incomplete."

**State 3 — No provenance-map, metadata exports exist (quick-skill path):**
`access.json` gives `state` 3: no provenance map entry (typical for quick-skill output), so `metadata.json`'s `exports[]` array, its `metadataExportCount` names, is the export name list. Coverage check becomes a self-consistency comparison: are all names in `exports[]` documented in SKILL.md with description, parameters, and return type? Signatures cannot be verified. Set `analysis_confidence: metadata-only`.

**State 4 — No local source, no forge-data, remote tools available:**
`access.json` gives `state` null (no map entry and no metadata export), but remote reading tools (zread, deepwiki, gh API, or similar) are available and `source_repo` is set in metadata.json: read the entry point remotely to build the export inventory from scratch. Name-matching only, no AST. Set `analysis_confidence: remote-only`.

**State 5 — No source access at all:**
If none of the above succeed, fall through to docs-only mode (as defined in coverage-check.md Section 0: pre-analysis source type detection). Set `analysis_confidence: docs-only`, and write `docsOnly: true` to the frontmatter of `{report_file}` beside the `analysisConfidence` write below, since coverage-check §0 wrote `false`. Warn: "**No source access available.** Coverage check evaluates documentation self-consistency only. Re-run with local clone or remote access for source-backed verification."

Set `analysis_confidence` in context for use in Section 2 analysis depth, step 5 output, and step 5 scoring, and write it at once to the frontmatter of `{report_file}` (init.md §6c created it) as `analysisConfidence: '{analysis_confidence}'`, again each time a later rule changes it (an empty barrel with no brief makes it `docs-only`), so the hard gate and scoring find the value resolved here on disk, never one recalled after the context was compacted; step-hard-gate.md §3 and score.md §7 write the same value again. It names the source access only: tooling health is `toolingStatus`, which init.md records, and the two never overwrite each other.

**Confidence tier mapping:** `full` = T1, `provenance-map` = T1, `metadata-only` = T1-low, `remote-only` = T1-low, `docs-only` = T3. This aligns with the T1/T1-low/T2/T3 scale used across all SKF workflows.

**Degradation notice rules:** at `provenance-map`, `{run_dir}/access.json` `degradation` picks the notice, from the provenance map entries' `confidence` labels (`provenanceConfidence`). Every other access below `full` takes the `low` notice whatever `degradation` says, a State 1 run a later rule made `docs-only` (its `degradation` null) included:

- **`all-t1`** (every entry T1, AST-verified): the provenance-map data is already at highest confidence. Do not recommend re-running with a local clone: it would produce identical results. Use: "Resolved via: provenance-map (T1 AST-verified at compilation time). Local clone not required: provenance data is already at highest confidence."
- **`mixed`** (some entries T1): report the breakdown, each `provenanceConfidence` label after its count, and recommend a local clone only for the entries that are not T1: "Resolved via: provenance-map ({count} {label}, one for each `provenanceConfidence` label, as 12 T1, 3 T1-low). Re-run with local clone to upgrade the entries that are not T1 to full AST verification."
- **`low`** (no entry T1, and every access but `full` and `provenance-map`, a docs-only run's too, with or without an `access.json`): keep the standard recommendation: "Re-run with local clone for full AST-backed verification."
