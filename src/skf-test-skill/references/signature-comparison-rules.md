# Signature Comparison Rules

Every signature judge compares by these rules: coverage-check.md §1's split-body cross-check, its §2 judge (or the main thread in its place), its §5b split-body Source (the Split-Body Sources section of coverage-check-branches.md), coverage-check-tiers.md's fallback per-file scan and coherence-check.md §4's reference judge (its `signature_match`). They decide what is a mismatch and how to tag one; each judge returns the JSON its step gives.

Two of them, coverage-check.md §2's judge (or the main thread in its place) and coverage-check-tiers.md's fallback per-file scan, also give each result an `undecided` list, empty when these rules leave none of its readings open: each reading that a mismatch it reports, or one it leaves out, rests on, where no rule settles the shape or two rules settle it differently. Each item is `{"export", "at", "rule", "reading", "other_gap"}`: the name, the declaration's `file:line` (or null), the rule that leaves it open (the sentence, quoted), the reading taken, and what the other reading would give (a Critical mismatch, a Low or Info one, or no mismatch). `score-signatures.py` drops, with a warning, an item that is no object, leaves `export`, `rule`, `reading` or `other_gap` blank or gives a blank `at`, never refusing the result for it, and carries each other one into `signatures.json`, whose items the Coverage Analysis section lists under Borderline Calls.

## Reading a form

A form claims only what it writes, and only what it claims is compared. Its parameter list claims each parameter it lists, in that order, and no other: a parameter it leaves out is one it says the export does not take (Difference tags say when that is `omitted-optional`). A type or a return type it does not write claims nothing (Annotations). An entry with no `params` key and no usage form writes no parameter list: it claims nothing about parameters, and only what it writes, such as its return type, is compared. `params: ""` or `[]` claims the export takes none, as an empty list of bare names (below) does: a required parameter the source takes is a mismatch, and an optional one is no difference, as for an empty call.

A name written with empty parentheses, or with only `...` or `…` between them, in running text or a description cell is a mention, not a form, whatever comes before the name (`await`, `new`, an assignment, a receiver or a module path): it claims nothing and is not compared, unless a return type follows its empty parentheses (`run_migrations() -> list[str]`), a signature whose empty list claims the export takes none. A description cell is any table cell but an export table's first cell and a cell whose column writes the call or signature, by its role (Signature, Props, Params, Parameters, Arguments, Usage, Syntax, Example and the like); a heading or an export table's first cell that writes `name()` is a form, an empty call (below). A name written with arguments in running text or a description cell is a call (below), not a list of bare names, whatever comes before the name, unless it writes a parameter type, a `?`, a bare `*` or `/` (no call writes one), or a return type with no `await`, `new`, assignment, receiver or module path before the name (`await coco.mount(fn) -> Handle` is a call).

Three kinds of form do not claim a complete parameter list:

- A call or usage example passes values (literals, variables, `name=value`): `RecursiveSplitter()`, `embed(text, model=m)`, `<Canvas of={X} />`. It is compared as a call: each argument it passes must exist, by position or by name, and every required parameter must be passed; an optional parameter it leaves out is no difference. An empty call `X()` written as a call example (in a heading, an export table's first cell, a call or signature column or a fenced example, never a mention) is one too, so it matches a source whose parameters are all optional. A component usage `<X a={x} b="y" />` reads as a list of bare names of the props it sets, and a call `f(a, b)` as its arguments in order, each the parameter at its position (or, written `name=value`, the one it names). A JSX spread (`{...props}`) or children can pass a required prop, and a call's `...args` a required parameter, so neither leaves one out. A Python `*items` argument can pass every parameter a caller may pass by position from its position on, and a `**mapping` argument every one a caller may pass by name, so neither leaves such a parameter out (`Settings(**config)` matches `__init__(self, host, port)`), while the arguments the call writes beside them are still compared (`Settings(**config, debug=True)` is a mismatch when the constructor takes neither `debug` nor `**kwargs`); a `*items` never passes a keyword-only parameter, nor a `**mapping` a positional-only one. A `*items` with no parameter left to pass (none a caller may pass by position from its position on, and no `*args`), or a `**mapping` with none left that a caller may pass by name and no `**kwargs`, passes arguments the declaration does not take, and a parameter a literal, variable or `name=value` argument of the call already passes is not left: `f(*items)` against `def f()` and `f(a, **options)` against `def f(a)` are mismatches, even though each call runs when its unpacking is empty. An entry's `usage_signature` written as a usage is read this way, and each usage in a list of usages is compared as a form of its own, under its entry's `form` index. A call written with placeholder names (`await coco.mount([subpath,] process_fn, *args, **kwargs)`), which the inventory contract records as a usage, is read the same way: its names are arguments at their positions, never parameter names, its `*args` and `**kwargs` unpack as above, and a bracketed argument (`[subpath,]`) is optional, so the call is compared with and without it, each as a call.
- An ellipsis (`...` or `…`) in a list stands for members it does not show and claims nothing about them: `(...)` and `(tasks, data, dataset, ...)` leave out no parameter.
- A list of bare names, with no type, default or `?` (`connect(host, port)`, `({ themes, defaultTheme })`), names parameters without claiming the list is complete: an optional member it leaves out is no difference, a required one is a mismatch. An entry's `params` written as such a list is read this way, whatever the names; a call expression comes as a usage (inventory-contract.md) and is read as a call (above).

A form that writes a type or a default for a parameter (`(date: Date) => string`) claims its list is complete: an optional parameter it leaves out is an `omitted-optional` difference (Difference tags). A parameter table (inventory-contract.md) is such a form, its rows read in order as one typed parameter list.

Optionality is stated only by a default, a `?` (on the name, or as `?:`) or an optional marker: `optional` in a docstring-style list, a Required column, a Default cell that gives a value. A type never states it, and an empty Default cell states nothing. A list of parameters or props, or a table, that states optionality for none of its members states none, and optionality is not compared: `connect(host: str, port: int)` matches `def connect(host: str, port: int = 5432)`. Once a list states optionality for any member, each member it writes with no mark, unless it is rest or variadic, claims to be required; a Default cell and a destructuring default mark only their own member (Components). A default's value is not compared: it only marks its parameter optional.

A form that opens with text the skill states once for several names, then `; ` and the name's own members (inventory-contract.md), writes both: the members the shared text states are members that form writes, read before its own. A name listed bare beside such shared text, with no parameter list, call or signature of its own, is a mention there, not a form: it claims nothing and is not compared. A whole parameter list, call or signature written once for every name a place lists (one Signature cell for a row that lists `get` and `head`) is no such shared text: it is each of those names' own form there.

In a language without keyword arguments (TS/JS, Go, Rust, Java, C, C++), leaving out an optional parameter that comes before one the form writes shifts the caller's positions: that is a mismatch, not `omitted-optional` (`slice(str, end?)` against `(str, start?, end?)`).

The names of Python's `*args` and `**kwargs` are never compared (`**kwargs` against `**options` is no difference), and the parameters after `*` or `*args` are compared by name, not order. A positional-only `/` or keyword-only `*` marker the form leaves out is not compared, and one it adds where the source has none is no difference: calls that follow the form are valid.

A call to a class is compared with its constructor: in Python, the parameters after `self` of the `__init__` the class declares, else those after `cls` of its `__new__`, else its nearest base's in method resolution order (`object`'s takes none); a dataclass, attrs class, pydantic model or NamedTuple that declares no `__init__` with the fields it generates, in declaration order, base fields first, a default marking a field optional, a field kept out of the constructor (`init=False`, a `ClassVar`) none of them, and a pydantic model's keyword-only; a TS/JS class with its `constructor(...)`, else its nearest base's; a class in another language with the constructors it declares, read as Overload sets says. Any other form that documents a class is compared with that same constructor. A component is compared by its props (Components), not its constructor. A call to an instance is compared with its class's `__call__` (`fn = _FunctionDecorator()`, then `fn(memo=True)`), its overloads read as Overload sets says, and a name bound to a class with that class's constructor (`Symbol = core.Symbol`, whose stub declares `__new__(cls, name: str)`). A leading receiver the source writes (`self`, `cls`, `&self`, `&'a self`, `&mut self`, `mut self`, `this: T`) is never compared, and a form's own leading receiver is dropped only when the source leads with one too: `(self, a)` against `def f(a)` is a mismatch. An argument past the parameters a declaration takes by position exists when it takes `*args`, a TS/JS `...args`, Go's `...T`, Java's `T...`, C#'s `params T[]`, Kotlin's `vararg` or a C or C++ `...`, and a keyword no parameter names exists when it takes `**kwargs`, so `Task(fn, max_chunk_size=512)` matches `__init__(self, executable, *args, **kwargs)`; a pass-through `__init__(self, *args, **kwargs)` is compared as written, so any call matches it. A class whose constructor is written only in a package outside the source tree (one that declares none over another package's base, such as `Exception`, or that a metaclass from there builds) has its parameters left uncompared and counts as matching, as such a declaration does (below); a class with generated fields is still compared with them, and one whose bases declare no constructor before `object` takes none.

The source's declaration decides: the documented form is compared with the parameters, the optionality and the annotations the signature declares, with one exception, a return annotation the body contradicts (Annotations).

A const annotated with a function type declares that type's parameters: `export const build: ViteBuilder['build'] = async ({ options }) => ...` takes the one parameter `ViteBuilder['build']` names, and the arrow's destructuring is that same parameter. A form may name it as the type does or destructure it as the arrow does, and a destructuring that names only some of the type's properties, in the arrow or in the form, does not read as a narrower type. A declaration whose parameter list is written only in a package outside the source tree (a binding destructured from a value cast to `typeof domTestingLibrary`, or `const spyOn: typeof vitestSpyOn = (...args) => ...`) has its parameters, their optionality and its return left uncompared and counts as matching, as a component whose props type lives there does (Components).

In the split-body cross-check both forms are documented: each is read by these rules, a type, return type or type arguments one of them leaves out are not compared, and a parameter's optionality is compared only when both forms state it. A parameter type one form writes that names some of the members of the other form's union agrees with it, in either direction, as it does against the source (Annotations): `node_name: list[str]` matches `node_name: list[str] | None = None`. A return type gets no such reading: one form's return type that leaves out a member of the other form's union disagrees with it, since a caller following that form is not told it can get that member back, so `-> Node` against `-> Node | None` is a mismatch. A leading receiver (`self`, `cls`, `&self`, `&'a self`, `&mut self`, `mut self`, `this: T`) that one form writes and the other leaves out is never compared: neither form is the source, so each form's own leading receiver is dropped before the two are compared. The forms one file writes for one name as an overload set are read as one set, as Overload sets says. An ellipsis claims nothing about the members it stands for, required ones included. A call, a list of bare names or a form its own file labels partial (each side's label is read from that side's file, not from the export's one `signature_form`) may leave out a parameter the other form does not state as required, unless leaving it out shifts a caller's positions (a language without keyword arguments, as above); any other form claims its list is complete, so leaving out a parameter the other writes is a mismatch (inventory-contract.md's examples). Each export's form is read alone: what the rows of other exports write, in the same table or file, states nothing about it, so `(action, sink, tracking_record, child_invalidation)` matches `child_invalidation: X | None = None` even when every other row of its table writes its defaults. Forms of one name attributed to different declarations of it are two exports, never compared with each other in the split-body cross-check: their own citations, read at each form's inventory `at` as inventory-contract.md says, name two declarations, or coverage-check.md §2's `bound` binds them to two, a declaration being one of the name's surface records or one `surface.json` lists in `otherDeclarations` (each judge reads the signals it has). A judge without the surface (coverage-check.md §1's reader) counts two declarations only when the two forms' own citations name two different files and the skill presents the forms as different things (another owner, module or import path); a citation of a re-export (a package `__init__` or index file the skill shows passing the name on) names no declaration, and when unsure the forms are compared as before. Each is compared only with the forms attributed to its own declaration, a form attributed to neither is a mismatch only when it contradicts the forms of both, and §2 holds a bound form to its bound declaration alone and an unbound one to the check's candidates (below).

A name the skill documents in several forms (a brief usage in SKILL.md, a full props list in a reference file) comes with `alternatives`: coverage-check.md §2's check lists them after its `documented` form, and the fallback per-file scan's `documentedAlternatives` holds them by name. Compare the declaration with each form the check offers, each by its own reading rules, and report a mismatch for each form that does not match, with its index as `form` (0 is `documented`, 1 the first alternative), its `documented_sig` written as that form and its `difference` tagged against it. With `candidates`, a form matches when it matches any candidate, and its mismatch is reported at the closest candidate. A form the check binds (`bound`: its own citations name one declaration of the name) is compared with its bound declaration alone, and its mismatch is reported there, at that declaration's file and line, whatever the check's location and candidates.

## Components

A component is an export the source declares as one: a function that takes one props object (plus a `ref`, for `forwardRef`) and returns JSX, an element or `null`, or a value the source declares as a component type, a wrapper's result, a class component, a `defineComponent` result or a Svelte component, in React, Preact, Solid, Vue or Svelte. A function with several positional parameters is a function, whatever it returns (`flexRender(Comp, props)`, `createPortal(children, container)`). A component's signature is its props `P`: a function component's props type, a class component's props type argument, a Vue component's `props` option or `defineProps` type or runtime object, or a Svelte component's props (`$props()`, or its `export let` declarations).

`FC<P>`, `React.FC<P>`, `FunctionComponent<P>`, `ComponentType<P>`, a `memo`, `forwardRef` or other higher-order component result over `P`, and `(props: P) => JSX.Element` (or `ReactElement`, `ReactNode` or `null`) are one contract, the props `P`: a component's return type and its wrapper are never compared. Callers set props by name, so their order is never compared.

A component's own props are the members written in its package: its interface or object type, object literals intersected into it, and members computed from its own code (`VariantProps<typeof buttonVariants>`). Members of a type from another package (`React.ComponentProps<"button">`, `HTMLAttributes<...>`, `ComponentProps<typeof Link>`) are inherited, as are the `ref` a `forwardRef` result takes and the optional `children` of `PropsWithChildren<P>`. A prop the form writes must exist on `P`, own or inherited. A component whose props type lives in a package outside the source tree (`const Tabs = TabsPrimitive.Root`) has its props left uncompared: only that it is a component is checked.

A prop the form writes that `P` lacks, or a type or an optionality it writes that the source contradicts, is a mismatch. So is a required own prop it leaves out, and a required inherited one (a `Link`'s `href`) left out of a full form. An optional own prop a typed props list or a table leaves out is an `omitted-optional` difference; one a list of bare names or a usage leaves out, and an optional inherited prop, is no difference. A rest element in a component's destructured props form (`({ className, variant = "default", ...props }: NativeButtonProps)`) stands for every prop of `P` the form does not name, own or inherited, required ones included, so the form leaves none of them out, and the rest's own name is not compared as a prop. `| null` and `| undefined` on an optional prop are no difference (`VariantProps` adds both). A props type name the form writes that the source does not declare (`Button(props: ButtonProps)` against a source with no `ButtonProps`) is not compared by name, only the props the form lists. Values in a usage example (`variant="subtle"`) are not compared.

A props list states optionality as Reading a form says: `({ of, meta, story })`, or a list of names, states none, and in an object type literal (`{ of?: X; meta: M }`) that states it for any member, each member written with no mark claims to be required. A table states optionality by a Required column, a `?` on a prop's name or a Default cell that gives a value; its Type column states types, never optionality. A Default cell with a value marks only its own row optional and an empty one states nothing, so Create Skill's `| Prop | Type | Default | Description |` table never reads a prop with an empty Default cell as required. A destructuring default (`({ of, meta = {} })`) likewise marks only its own member, and the others state no optionality.

## Annotations

- A parameter written without a type is not compared on type: its name and order are, and its optionality as Reading a form says. Bare `*args` matches `*args: P.args`, and `**kwargs` matches `**kwargs: P.kwargs`. A parameter's or prop's type written as a description is read as a return type is (below): a description followed by a type (`Pydantic BaseModel`) states that type, and text that names no type (`Union (many)`) states none, so it is not compared, as an unwritten type is not.
- A return type the form does not state is not compared. A form states one when its entry has a non-blank `return_type` or the form writes one: after `->`, `=>`, `→` or `):`, or in its language's own position (Go's result list after the parameters, the type before the name in C, C++ and Java). A blank `return_type` (`""`) states none, so an entry with `params: ""` and no return type matches `def f() -> None`.
- A return written as names of values rather than types, a parenthesized list of names such as `→ (nodes, edges)` (after the arrow or in `return_type`), states no return type, so no return is compared. A type name written alone stays a type, lowercase ones included: `-> list` and `→ str` state one. A bracketed or braced list of value names, such as `→ [state, setState]` or `=> { data, error }`, likewise states none, while a single name (`→ result`), a list that writes a type among its names (`(nodes: list[Node], edges)`) and a description followed by a type (`HTML str`) each state one.
- A return written as a type followed by other types it names as alternatives, in a parenthetical or a list, each with an optional condition (`RememberResult (DryRunEstimate with dry_run=True, PresortReport with dry_run="presort", or dict)`, `GraphSnapshot for "pydantic", ExportResult for "cogx"`), states the union of every type it names, and the words that name no type (`with dry_run=True`, `for "pydantic"`) state nothing: it matches the source's union when it names every member and no other: a member it leaves out is a mismatch (below), and so is one the source never returns. A type a parenthetical names other than as an alternative (`Response (see Request)`) is description, so only the type before it is stated.
- A type the source leaves unannotated, on a parameter or a return, is not compared, except that a TS/JS parameter with a literal default has that literal's type: `pageSize = 20` is a `number`, so `pageSize?: string` is a mismatch. An unannotated return stays uncompared.
- A documented parameter type that names some of the members of the source's union is no mismatch, since a caller passing it makes a valid call (`schema: VectorSchemaProvider` against `VectorSchemaProvider | MultiVectorSchemaProvider`); a documented return type must cover every member the source can return.
- Type arguments the form leaves out are not compared: `dict` matches `dict[str, Any]`, and `list[dict]` matches `list[dict[str, Any]]`. Type arguments it writes are: `dict[str, int]` against `dict[str, str]` is a mismatch.
- A documented return type that matches what the body demonstrably returns, where the declared annotation says otherwise, is a mismatch tagged `annotation-contradicted` with `evidence_line`, the body line that returns that value: the skill documents what callers get, and the contradiction is the source's, which `score` reports without blocking. Against a declaration annotated `-> Callable[[], Callable[[], None]]` whose line 19 returns the function, `-> Callable[[], None]` is tagged with `evidence_line` 19. Tag it only when you can name that line: a body line that starts with `return`, or the declaration line itself when its own expression body follows its parameters there (`=> expr`, a Python `def ...: return x`). A Rust tail expression, a Kotlin or Scala expression body and a Ruby implicit return have no such line and cannot be tagged: there, as when you cannot name the line, the declaration decides. A judge whose result has no `difference` field (coherence-check.md §4's `signature_match`, coverage-check.md §5b's split-body Source) reads such a documented return type, at a line it can name, as agreeing with the source: a match for `signature_match`, and for §5b a form that agrees with the source. It holds for a return type alone, never a parameter's annotation.

## Equivalent spellings

Two spellings of one type are no mismatch:

- `Optional[X]`, `Union[X, None]` and `X | None`; `Union[A, B]` and `A | B`; a union's members in any order (`None | X`, `B | A`).
- `A / B` written between types in one parameter's or prop's type and `A | B`, as a table's Type cell, where a bare `|` cannot stand, writes a union: `str / list[str] / None` and `str | list[str] | None`. A `/` written alone in a parameter list stays the positional-only marker (Reading a form).
- `typing`'s `List`, `Dict`, `Tuple`, `Set`, `FrozenSet` and `Type` and the builtins `list`, `dict`, `tuple`, `set`, `frozenset` and `type`.
- A name with or without the module or namespace path it is written through, such as a `typing.`, `collections.abc.` or `React.` prefix or a module or namespace the source imports under its own name or an alias, when both name one declaration: `React.ReactNode` and `ReactNode`; `environment.Environment`, after `from . import environment`, and `Environment`; `z.ZodType` and `ZodType`. Two declarations that only share a name stay two types.
- A quoted forward reference and the name it quotes: `"Node"` and `Node`.
- `Array<T>` and `T[]`; `ReadonlyArray<T>` and `readonly T[]`.
- A type alias the source declares and the type it names. A type name a form writes means the type the skill documents or the package exports under that name, and the source file's own declaration of it only when there is none, or when the file declares the name other than as an alias (a local `interface Options`). A name the source writes means the declaration in its file's scope, a local alias read through the type it names and an import alias as the type it imports: the documented `ThemesParameters['themes']` matches a return of the local `type ThemesParameters = Parameters['themes']`, declared over `import type { ThemesParameters as Parameters }`. When such an alias reuses a name the skill documents or the package exports, a mismatch's `source_sig` writes it as the type it names, by its exported name when it has one (`ThemesParameters['themes']`, not the local `ThemesParameters`), so the form the gap asks for matches the source.
- Type variables renamed consistently: `(a: T) -> T` against `(a: U) -> U`, but not `(a: T, b: U)` against `(a: U, b: U)`.
- Type arguments the source leaves out are not compared either: the form's `dict[str, Any]` matches the source's bare `dict`.
- A union of callables that take the same parameters and one callable returning the union of their returns: `Callable[[A], X] | Callable[[A], Y]` and `(a: A) -> X | Y`.

## Overload sets

A declaration opening an overload set (Python `@overload` stubs, TS bodiless signatures) is read through its implementation: a documented signature matching the implementation or any overload is no mismatch, and so is one whose parameter types are, position by position, the unions of the overloads' types.

A name declared several times with different parameter lists and no implementation they share (overloaded constructors in Java, Kotlin, C# and C++, a Kotlin class's primary and secondary constructors among them, and overloaded methods in those languages and functions in Kotlin and C++) is one set too: a documented form that matches any of its declarations is no mismatch (`new Client("localhost", 8080)` matches `Client(String host, int port)` beside `Client(String host)`).

In the split-body cross-check, the forms one file writes for one name as an overload set (`@overload` stubs or TS bodiless signatures, and the implementation after them when the file writes it, or the several declarations of a name the paragraph above makes one set) are one documented overload set, read as a source's is: a form on the other side that matches its implementation, any of its stubs or declarations or, position by position, the unions of the stubs' parameter types is no mismatch, so a form that defaults `format` matches a set whose stub requires it and whose implementation defaults it, and `new Client("localhost", 8080)` matches a file's `Client(String host)` and `Client(String host, int port)`. The set's own forms are compared neither with each other nor with its implementation.

## Difference tags

A fact these rules leave uncompared is no difference. A mismatch carries `difference` when the two differ only in one of these ways, else no key: `parameter-name` (only parameter names differ: types, order, optionality and return type equal; a destructured property is part of a type), `omitted-optional` (the documented form leaves out only members the source marks optional) or `annotation-contradicted` (only the return type differs: `documented_sig` and `source_sig` write the same parameters, or the form writes no parameter list, and the body returns the documented type at the mismatch's `evidence_line`, as Annotations says). A parameter or field with a default or a `?`, or a variadic parameter (a TS/JS rest parameter, a Python `*args` or `**kwargs`, Go's `...T`, Java's `T...`, C#'s `params T[]`, Kotlin's `vararg` or a C or C++ `...`), is optional; a Rust `Option<T>` field a struct literal still requires is not. A renamed component prop is never `parameter-name`: callers set props by name, so it is a mismatch with no tag. Tag it in any language and form: `score` (coverage-check.md §2b) checks the facts. The example in coverage-check.md §2, tagged `omitted-optional`, stays Critical against a full form.
