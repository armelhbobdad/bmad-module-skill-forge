# Version-nested skills layout defeats flat SKILL.md scanners

Exported skills live at `{skills_output_folder}/{name}/{version}/{name}/SKILL.md` with a `{name}/active` symlink (`src/knowledge/version-paths.md`), so any helper that walks the skills folder and checks `skills/{child}/SKILL.md` finds nothing. `src/shared/scripts/skf-enumerate-stack-skills.py` did exactly that and returned `{"skills": [], "cycles": [], "warnings": []}` on a real project while its flat-layout test fixtures passed; commit 62a94a18 added `_resolve_package_dir` (a flat root `SKILL.md` first, then the `active` symlink, then the highest semver directory). c6852cdb (PR #509) replaced it and `_inner_package` with `_skf_package`, which reads only a package whose `metadata.json` carries the SKF marker: first the version `active` names, then the highest marked version, then a marked flat root, skipping `.skf-` names and any version folder or package that is a link; a folder that looks like a skill but holds no marked package goes to the roster's `not_skf_output`, or to `warnings` when SKF cannot read a candidate. A new scanner that must count only SKF output should carry pinned copies of the inventory's marker checks (`SKF_GENERATORS`, `_has_skf_metadata`, `_is_link_or_junction`, `_is_marked_version`, `_looks_like_skill`), each under the `Keep identical to` and `test/test-skf-skill-inventory.py pins the copies` comments, name the new file in the inventory copy's own `Keep identical to` comment, and add a `TestSkfMarkerParity` row for each copy plus the new file in that class's file lists (`test/test-skf-skill-inventory.py`). It should not use `resolve_active_version` (`src/shared/scripts/skf-skill-inventory.py`) alone: that follows `active` without checking the marker, even to a folder outside the skill group, has no fallback to the highest version and returns nothing for a flat skill, so it reads a version-nested skill SKF did not generate as one of SKF's own; the same file's `_marked_active_version` is the marker-aware way to resolve `active`. Build fixtures with `_make_nested_skill` from `test/test-skf-enumerate-stack-skills.py`: like `_make_skill` it defaults to `marked=True` but writes the marker only when a `metadata` dict is passed (`generated_by: create-skill`, unless the dict sets its own `generated_by`), so pass one to model a skill SKF generated and add `marked=False` to model one it did not — a flat fixture cannot catch this failure.
