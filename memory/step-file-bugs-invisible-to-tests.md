# Step-file bugs mostly invisible to the test suite

`npm test` runs pytest over the ~58 `src/shared/scripts/skf-*.py` helpers, but the LLM-followed step files under `src/skf-*/references/` get only narrow mechanical checks: `test/test-skf-chain-reachability.py` (Stages-table paths exist, `nextStepFile` chain reachable), the skf-campaign linter `test/test-skf-campaign-stepfiles.py`, sentence pins such as `test/test-skf-ccc-reindex-prose.py`, `test/test-skf-update-source-tree-prose.py` and `test/test-skf-update-version-folder.py`, and, since commit 61d91c38 (#510, #512), checks on helper calls and paths. `test/test-skf-helper-call-contract.py` runs each placeholder call in fenced code or an inline code span through the helper's own argparse parser (helpers built on subcommands; `skf-manifest-ops.py` calls are checked against the commands its `main()` dispatches), `validate:refs` requires an installed twin before every `{project-root}/src/` path, and Test Suite 7 of `test/test-installation-components.js` resolves every ProbeOrder and frontmatter path in a temporary install; the contract test exists because rename-skill called `flip-link` on `skf-update-active-symlink.py`, which has only `update` and `verify`, so every rename of a skill with an active link rolled back with `write-failed` while the suite stayed green. Much stays invisible: the contract test ignores the interpreter in front of the placeholder (commit 7c3cc2b5 fixed three campaign helpers invoked as `uv run python <script>`, which would have failed with `ModuleNotFoundError`, latent because "the workflow has no end-to-end coverage yet"), and no general check covers calls to helpers without subcommands (only a few are pinned one by one, such as `TestCallersPassTheBody` for the managed-section helper), branch logic, prose meaning or Stages-table/GATE drift like the one found in skf-analyze-source. `test/test-skf-campaign-stepfiles.py`'s docstring records that both HIGH-severity Epic 4 findings lived in step files and were found by adversarial review, not tests. A green suite therefore does not validate a step-file change: after editing step prose, run the workflow live against a real repository (`@Ferris forge-auto <repo>` for the pipeline, or the single skill) or at least do an adversarial read of the changed step before calling it done.
